## Was neu ist

- `rules/merge-nur-sightline.md` (blockiert, Ereignis `all`, Bedingung `merge_attempt` = `merge`); die Logik steht nur in `hooks/guard.py`
  (`merge_attempt`, `merge_words`, `is_sightline`) und gilt über die Adapter für Claude Code und Codex.
- **Gesperrt:** `gh pr merge …` (auch `--auto`, `--squash`, mit `-R`), `gh api … -X PUT …/pulls/N/merge` (`--method`, `--method=`, `-XPUT`,
  Groß/klein), `gh api graphql` mit `mergePullRequest`/`enablePullRequestAutoMerge`, jeweils in jedem Segment einer Zeile (`&&`, `;`, `|`),
  nach `NAME=wert`, `env`/`command`/`exec`/`time`/`nohup` und in `bash|sh|zsh -c '…'` und `eval`; dazu `mcp__github__merge_pull_request`
  und `mcp__github__enable_pr_auto_merge`. Die Wörter liest `shell_segments` wie die Shell; ein Befehl in `echo '…'` oder `grep '…'` zählt nicht.
- **Frei:** `git merge origin/main` (main in den Arbeitsbranch holen), `gh pr view|create|list|checks`, `gh pr merge --help|-h`, `gh api` ohne
  `PUT`/`…/merge`, GET auf `…/merge`.
- **Sightline** ist, wer `CE_ROLE=sightline` setzt oder dessen Worktree unter `<git-dir>/ce-session.json` den reservierten Namen `Sightline`
  trägt (auch `Sightline · Cloud`; nicht `Sightlines-Prüfung`, `NotSightline`). Kein Repository, keine Datei, leerer Name = nicht Sightline = Sperre.
  Ein Lesefehler oder Fehler in der Erkennung lässt durch (Fail-open, wie jede Regel des Wächters).
- Meldung der Sperre: „Merge macht Sightline nach Prüfung – PR-Nummer und Head-SHA ins Postfach“ mit Hinweis auf `./ce session say`.
- Verdrahtung: Claude-Matcher in `hooks/hooks.json` um beide MCP-Werkzeuge erweitert (ohne das ruft Claude den Wächter für MCP nie auf);
  `codex_guard.normalize` reicht `mcp__…` mit Namen und Eingabe weiter (andere Regeln sehen MCP weiterhin nicht, Test bleibt grün). Der
  Codex-Matcher der Nutzer lautet danach `^(Bash|apply_patch|mcp__github__merge_pull_request|mcp__github__enable_pr_auto_merge)$`
  (`./ce plugins` schreibt ihn nicht von selbst; ohne die Erweiterung sperrt Codex nur die Shellwege). **Antigravity:** nur der Shellweg
  (`run_command`); MCP-Werkzeugnamen sind dort nicht gemessen.

## Grenzen (offen benannt)

- Eine Sperre auf Werkzeugebene ist keine Berechtigung: Wer `CE_ROLE=sightline` setzt, umgeht sie; die Absenderkennung ist wie bei der
  Freigabe per Post eine Vereinbarung. Der Merge über die GitHub-Weboberfläche, `curl` mit Token oder ein selbst geschriebenes Skript wird nicht
  erkannt. Wirksam gegen Versehen, nicht gegen Absicht.
- `gh pr merge` aus einem Skript (`./merge.sh`) oder über eine Variable als Programm sieht der Wächter nicht (wie bei `commit-on-main`).
