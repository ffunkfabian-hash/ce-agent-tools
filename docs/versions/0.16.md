# Agent Tools 0.16 „Tidemark“

Stand: in der Cloud umgesetzt und geprüft (445 Tests grün), Richter (Opus, Codex in der Cloud nicht verfügbar): Freigabe; gemergt (#15, `28714a8`), Proben am Mac und in der Cloud am 23.10.2026 (unten). Basis: 0.15.1 (b8792da).

## Anlass

Nach dem Rollout von 0.15.1 (22.10.2026) zeigte `claude plugin list` am Mac neun Installationen von ce-shared: die Nutzer-Installation
auf 0.15.1, aber sechs Projekt-Einträge auf 0.11.0 oder 0.13.0 – der Haupt-Checkout von Cube Escape, Worktrees von Claude und Codex.
Claude Code legt je Ordner (Checkout, jeder Worktree) einen Eintrag in `~/.claude/plugins/installed_plugins.json` an, der auf der
Version seiner Anlage stehen bleibt. `claude plugin update` bewegte nur den Nutzer-Eintrag; `--scope project` meldete in den
betroffenen Ordnern „already at the latest version“ und aktualisierte einmal den Eintrag eines anderen Ordners. Ein von Hand
geschriebenes Skript (Felder des Nutzer-Eintrags übernehmen, mit Sicherung) brachte alle neun auf 0.15.1. Eine Sitzung mit altem
Eintrag läuft ohne die Hooks der neuen Version (hier: ohne den automatischen Postfach-Wächter), ohne dass es jemand merkt.

Recherche (Doku von Claude Code, 22.10.2026): Auto-Update ist für Drittanbieter-Marketplaces aus und lässt sich mit `"autoUpdate": true`
am Eintrag in `extraKnownMarketplaces` einschalten; ob es Projekt-Einträge erfasst, ist nicht dokumentiert. Zu Worktrees und
Projekt-Einträgen gibt es gemeldete, unbestätigte Fehlerberichte (Worktree lädt den ersten Eintrag desselben Repos; veralteter Eintrag
meldet „already at the latest version“). Entscheidung des Nutzers: Vorschlag A – Auto-Update, möglichst nur die Nutzer-Installation,
dazu ein Sicherheitsnetz, das nicht von Claude Code abhängt.

## Umsetzung

- `tools/ce_plugins.py` (`./ce plugins check|fix`):
  - `check` listet alle Einträge der Plugins aus `ce-agent-tools` mit Bereich, Version und Ordner; Exit 1, wenn einer veraltet ist,
    sein Ordner fehlt oder der Marketplace-Klon eine neuere Version nennt als jede Installation (dann mit den Update-Befehlen).
  - `fix` zeigt im Probelauf, was sich ändert; `--apply` legt `installed_plugins.json.bak-<Zeit>` an und schreibt atomar. Veraltete
    Einträge bekommen Version, `installPath`, Commit und Zeit der neuesten Installation, deren Dateien vorhanden sind (der
    Nutzer-Eintrag gewinnt bei Gleichstand); Einträge verschwundener Ordner werden entfernt. Heruntergeladen wird nichts.
  - `--user-only` entfernt alle Projekt-/Lokal-Einträge, wenn ein Nutzer-Eintrag auf der neuesten Version besteht (Schritt 2 von A,
    erst nach der Probe am Mac).
  - Nur Plugins aus `ce-agent-tools` und nur das bekannte Listenformat; fremde Plugins bleiben unberührt. `CE_PLUGINS_DIR` für Tests.
- `hooks/session.py` (SessionStart): vergleicht die Version des geladenen Plugins mit der neuesten auf dem Rechner (Marketplace-Klon,
  alle Einträge) und warnt sichtbar (`systemMessage` und Kontext), wenn die Sitzung ein älteres ce-shared läuft. In der Cloud ohne
  Plugin-Ordner bleibt es still; ein Fehler der Prüfung kostet die Sitzung nichts.
- `ce_plugins.py` in `SYNC_FILES`, damit `./ce plugins` in jedem Repo läuft; Einbinden im README mit `"autoUpdate": true`.
- Nebenbefund: vier Tests der 0.15 (`test_postfach_watch`) setzten die Kommentarzeit fest auf `2026-10-22T18:10Z` und wurden rot,
  sobald die Uhr 30 min weiter war (der Wächter liest ab Reservierung bzw. Rückblick). Jetzt relativ zur aktuellen Zeit.

## Grenzen

- Die Ursache liegt in Claude Code; das Werkzeug umgeht sie und macht sie sichtbar. Ob `autoUpdate` Projekt-Einträge erfasst, ist
  nicht dokumentiert – die Warnung beim Start fängt beide Fälle.
- `installed_plugins.json` ist eine interne Datei von Claude Code; ändert sich ihr Format, bleibt `ce_plugins` still („unbekanntes
  Format“) statt zu schreiben.
