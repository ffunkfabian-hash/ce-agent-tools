# Agent Tools 0.14 „Crosstalk“

Fertig: in der Cloud umgesetzt und geprüft, auf den Arbeitsbranch gepusht (Ja des Nutzers 22.10.2026); Merge nach main und Rollout offen. Basis: 0.13 (dead54f).

## Anlass

Am 22.10.2026 reservierten der Formgen-Patch „Stützgriff“ und Toolgen 0.21 „Livery“ ihre Branches korrekt, im Postfach #16
stand aber nichts davon. Sightline erfuhr von beiden nur über eine Branch-Abfrage. Die Regel sah bis dahin vor, dass eine
Sitzung erst mit ihrer Abschlussmeldung schreibt; die Reservierung war ein stiller Branch-Push. Der Nutzer wollte, dass sich
Sitzungen selbst anmelden und auch untereinander schreiben können.

## Umsetzung

- `ce_session_name.py --reserve` meldet die Sitzung nach dem Push im Postfach an:
  `<Name> → Sightline: angemeldet`, Modellzeile (`--model`), Repo, Branch, Basis-Commit, Auftrag (`--about`) und der
  Wächterbefehl, mit dem andere sie erreichen. `--to` ändert den Empfänger, `--no-announce` lässt die Anmeldung weg.
- `--patch <kurzname>` reserviert Patches auf demselben Weg (`<agent>/<repo>-patch-<kurzname>`, Name `<Kürzel> Patch <kurzname> · <Ort>`).
  Patches reservierten bisher nichts und blieben dadurch unsichtbar.
- `ce_postfach.py say` (`./ce session say`): Nachricht im Regelformat (Kopf, Modellzeile, höchstens zehn Zeilen). Absender ist
  der beim Reservieren in `<git-dir>/ce-session.json` gemerkte Name, sonst aus dem Branch abgeleitet (`claude/tg-0.23-livery` →
  `TG 0.23 „Livery“ · Mac`). Der Wächter vergleicht Namen schreibweisenfest (Bindestrich, Umlaut, Groß/klein); Namen ohne Version
  müssen ganz passen (`CE Patch laser` ist nicht `CE Patch laser-seeder`). Empfänger: eine Sitzung, eine Rolle oder `alle`.
- `ce_postfach.py who` (`./ce session who`): Anmeldungen der letzten Tage mit der jüngsten Meldung je Sitzung.
- `ce_await_mail.py`: `→ alle:` in der Kopfzeile weckt jede wartende Sitzung außer der absendenden; ein zitiertes `→ alle:`
  weiter unten weckt niemanden.
- `ce_sync.py` kopiert `ce_postfach.py` mit; ein Test prüft, dass jedes von `ce` gerufene und jedes importierte Werkzeug synchronisiert wird.

Transport ist `gh api` wie beim Wächter. Gesendet wird nur aus einem Repo, dessen `origin` eine GitHub-URL ist; lokale
Origins (Tests, Bare-Repos) bleiben stumm, `CE_MAILBOX=0` schaltet es ab. Ein Wegwerf-Klon eines echten GitHub-Repos sendet. Schlägt das Senden fehl, steht der Text zum Einfügen in der Ausgabe;
die Reservierung bleibt bestehen.

## Grenzen

- Ein Empfänger je Kopfzeile, Doppelpunkt Pflicht (Regelformat). Namen ohne Version müssen ganz passen: `→ Sightline und Review:`
  oder `→ Sightline – Freigabe` ohne Doppelpunkt wecken nicht mehr (in 0.13 per Präfix schon).
- Ein Origin über einen lokalen HTTP-Proxy gilt nicht als GitHub-URL: Die Sitzung gibt den Text zum Einfügen aus, statt zu senden.

- Geweckt wird nur, wer einen Wächter laufen hat. Claude Code startet ihn im Hintergrund; Codex ohne Hintergrund-Wecken liest
  von Hand. Die Anmeldung allein weckt niemanden außer dem Empfänger.
- Direkte Sitzungsnachrichten von Claude Code (Peer-Messaging, Remote Control) werden nicht genutzt: Codex und Antigravity
  erreichen sie nicht, das Postfach bleibt der gemeinsame Kanal.
- Regeltexte in Nexogen (`templates/auftrag.md` Start-Check, `regeln-details.md` › Briefkasten) und der Rollout in die Fachrepos
  (`ce_sync`) sind eigene Schritte nach dem Merge.
