# 0.39.0 „Sunset“ – merge-check: gelöschte Tests, deren Code im selben PR entfällt

Sitzung `CE-AGENT-TOOLS 0.39 „Sunset“ · Mac` (Claude Opus 5.5, high). Entscheidung 304, Basis `main` f222344.

**Ergebnis:** `merge-check` zählt eine ganz gelöschte Testdatei nicht mehr als Abschwächung, wenn ihre entfernten Zeilen eine im selben PR gelöschte Datei nennen, die weder Test noch `.md` ist. Ein solcher PR bleibt immer bei Stufe 2, die Warnung nennt Datei, Zahlen und Quelle. Probe ohne `--ja`: Nexogen PR 76 und Agent Tools PR 45 sind grün, beide ohne „Tests abgeschwächt“.

Die Prüfung sieht nur, dass die Datei die Quelle nennt, nicht, dass sie nur diese Quelle prüft. Eine Testdatei für zwei Module fällt ganz heraus, wenn eines entfällt, und Code, der unter neuem Namen weiterlebt, sieht wie entfallen aus. Ein bloßer Dateiname trifft jede gleichnamige gelöschte Datei (`"config.json"` gegen `legacy/config.json`), `import json` trifft `scripts/json.py`, Fixtures außerhalb von `tests/` oder ein `conftest.py` im Wurzelordner gelten als Quelle, und Prosa in Importform (`import config file`, `export MSG="hello from 'config'"`) zählt als Import. Eine geänderte Testdatei ohne Patch neben einer ausgenommenen bleibt nur eine Warnung, wie auf `main`. Darum das Ja und die Warnung an den Richter. In die sichere Richtung bleiben rot: Pfade ohne Endung, mehrzeilige Importe, C#-`using`, Tests eines gelöschten `.md`.

**Lehren:** Ein Tor zu lockern heißt, die Lockerung selbst sichtbar zu machen: Warnung und Stufe 2 tragen die Sicherheit, nicht die Treffergenauigkeit. Ein Wort auf einer Importzeile beweist kein Modul: `from subprocess import run` gegen `src/run.py` kam erst beim Richter heraus, die eigenen Tests hatten nur `subprocess.run` geprüft. Wer Zahlen aus einer Summe nimmt, macht aus dem Rest eine Gutschrift: Neue Tests deckten sonst einen Verlust in einer dritten Datei.
