## Umsetzung

- Die Halterzeile bleibt `{"pid", "what", "checkout", "since"[, "resource"]}`. `status` liest zusätzlich, zur Abfragezeit:
  - Reservierung des Checkouts (`git rev-parse --absolute-git-dir` › `ce-session.json`: Name, Modell; älter als 3 Tage → „older reservation“), sonst Branch;
  - Prozesstabelle (`ps -A -o pid=,ppid=,command=`): Client = erster bekannter Vorfahr (Programmname oder `.app`-Bündel, auch `node …/claude`), Befehl des Halters, bis zu zwei Nachkommen („runs:“);
  - Laufzeit aus `since`; Wartende aus `ce_lock_status.waiting` unter ihrer Ressource.
- `shared`: hält ein `gpu`-Lauf die Barriere exklusiv, steht dort „barrier, held exclusively by the gpu run below“ statt „unknown“.
- Freie Ressourcen bleiben eine Zeile `free` (Format für Skripte unverändert). Jeder Fehler (kein `ps`, kein Git, fremde Zeile) lässt nur den Teil weg.

## Was es nicht kann

- Eine Sitzung ohne Reservierung (Haupt-Checkout, wie im Anlass `cubeescape-nexogen`) bleibt namenlos; Client und Befehl zeigen dann, wer es ist.
- Ein vom Client abgekoppelter Hintergrundprozess hat keinen Client-Vorfahren mehr.
- Repos lesen die Werkzeuge über ihren Pin (`tools_version`): `./ce lock status` dort zeigt das erst nach dem Pin auf 0.24; das Plugin
  direkt (`python3 ~/.claude/plugins/marketplaces/ce-agent-tools/plugins/ce-shared/tools/heavy_lock.py status`) sofort nach dem Update.
